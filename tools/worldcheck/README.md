worldcheck

Generates test worlds on the development dedicated server and analyses their region files.
Python 3 standard library only (screenshot.py also needs python-xlib); run from the repository root.

```
# Vastlands world, seed 20261018, 16x16 chunks around 0,0 (writes run/eula.txt: you accept the Minecraft EULA)
python3 tools/worldcheck/generate.py --level-name vl_a --fresh --accept-eula

# A larger square somewhere else (2R x 2R chunks, R <= 32)
python3 tools/worldcheck/generate.py --level-name m1 --center 300 5000 --radius 16 --fresh

# Same seed again, and a vanilla baseline
python3 tools/worldcheck/generate.py --level-name vl_b --fresh
python3 tools/worldcheck/generate.py --level-name vanilla_a --level-type minecraft:normal --fresh

# One world, or a comparison of two
python3 tools/worldcheck/analyze.py run/vl_a
python3 tools/worldcheck/analyze.py run/vl_a run/vl_b

# Ground heightmap: relief PNG, chunk-border seams, comparison with the terrain model or another world
./gradlew terrainPreview --args="--seed 20261018 --center 0 0 --size 256 --scale 1 --heights run/vl_a-expected.bin"
python3 tools/worldcheck/heightmap.py run/vl_a --png run/vl_a.png --expected run/vl_a-expected.bin --compare run/vl_b

# Forests (needs numpy, PNGs Pillow): leaf distances, trunk support, trees, canopy, floor, seams;
# --compare: identical tree blocks with another generation of the same square
python3 tools/worldcheck/forestcheck.py run/m1 --png run/m1-forest.png --compare run/m1b

# Natural formations (needs numpy): floating blocks, pointed dripstone that would break, huge
# mushroom faces, materials, and with --compare (the same square generated by other code) the
# materials before and after and the seams of the added blocks
python3 tools/worldcheck/naturecheck.py run/n1 --compare ../vastlands-base/run/base_n1 --json run/n1-nature.json

# In-game screenshots (dev client under Xvfb; NAME:X Y Z YAW PITCH, yaw 0 = south, 180 = north)
pip install python-xlib
python3 tools/worldcheck/screenshot.py run/m1 --out run/shots --shot "ridge:300 300 5200 180 10"
```

- `generate.py` overwrites `run/server.properties`, starts `./gradlew runServer`, moves the world
  spawn to the centre of the square with `gamerule spawnChunkRadius` set to the radius (the spawn
  ticket generates chunks in parallel, like a player's view distance; `/forceload` would generate
  one chunk at a time on the server thread), waits until every chunk of the square is fully
  generated and saved, probes the build limits with `setblock` over RCON (port 25575), stops the
  server, and writes `run/<level-name>/worldcheck.json` with `generation_seconds` and
  `chunks_per_second` (it checks every `--poll` seconds, default 10: use 2 for timings). Server
  output goes to `run/worldcheck-<level-name>.log`.
- `analyze.py` reports the section range, bedrock floor, block composition per height band and
  surface heights; with two worlds, the share of identical blocks, biomes and surface heights.
  The probe column is excluded. It reads every block, so keep it to squares of about 16x16 chunks.
- `heightmap.py` only reads the saved heightmaps, so it handles large squares. Ground is
  min(OCEAN_FLOOR, MOTION_BLOCKING_NO_LEAVES); it prints the mean and maximum height step between
  neighbouring columns inside chunks and across chunk borders (a seam would show up as a larger
  step across borders) and, with `--expected`, how often the ground matches the terrain model.
- `screenshot.py` copies the world to `run/saves/<world>-shots` with commands enabled, starts the
  dev client with `--quickPlaySingleplayer`, sets noon and clear weather, hides the HUD and saves
  one F2 screenshot per shot. Keep shots inside the generated square: chunks outside it are
  generated by the integrated server while the client waits.
- Vanilla decoration is not bit-for-bit reproducible between runs (features crossing chunk borders
  depend on generation order). Judge determinism against a vanilla-vs-vanilla baseline.
